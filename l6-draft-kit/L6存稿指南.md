# L6 级 SVG 动效 · API 直推草稿箱 · 复刻指南

> 目标读者：需要在微信公众号草稿箱里获得 **L6 完整主题动效**（SVG 动画）的合作者。
> 本方案已于 2026-09-03 真实公众号实测打通（存储正文动画标记 100% 存活）。
> 工具：本目录 `l6-push.js`（单文件，无第三方依赖，Node.js 20+）。

---

## 一、30 秒懂原理

1. 微信 `draft/add` API **完全接受 SVG 动画**（SMIL `<animate>`/`<animateTransform>`，含线条动画、`begin` 属性、`data-*` 属性），存储后原样保留——已用 14 个对照探针实验证实。
2. 官方 CLI 的 `draft` 命令有两道关卡把动效挡住了：
   - 渲染阶段无条件强制 `static=true / motion=false`（动画根本没被渲染）；
   - `compactForWechat` 默认删除全部 `<svg>`（`--preserve-visuals` 只能保住静态框架）。
3. 本工具复用官方 CLI 安装目录的渲染管线，**只放开这两道关卡**，其余（图片上传、素材替换、回读核对）与官方完全一致。

## 二、前置条件

| 条件 | 说明 |
|---|---|
| Node.js ≥ 20 | `node --version` 确认 |
| 官方 CLI 已安装 | 默认装在 `~/.local/share/yituo-hub-gzh`（`install.sh` 一键装） |
| 公众号凭证 | 环境变量 `WECHAT_APPID` / `WECHAT_APPSECRET`，或 `~/.config/yituo-hub-gzh/config.json`（与官方 CLI 同一份配置） |
| IP 白名单 | 本机出口 IP 已加入公众号后台白名单（设置与开发 → 基本配置）。若报 `40164`，错误信息里就是该加的 IP |

## 三、快速开始

```bash
# 1. 写一篇短文 card.md（正文建议 ≤ 300 字，1~2 个小节，文末放一张二维码图）

# 2. 体积审计：看哪些主题塞得下（纯本地渲染，不发请求）
node l6-push.js card.md --audit

# 3. 挑一个 ✅ 的主题，L6 直推
node l6-push.js card.md --style night-editorial --level L6 \
  --cover example-cover.png --author "你的署名" --digest "摘要"
```

成功输出（关键字段）：

```json
{
  "ok": true,
  "storedAnim": 8,          ← 微信存储正文里的动效标记数
  "motionSurvived": true,   ← 动画确实活着
  "verified": true,         ← 回读核对通过
  "published": false        ← 只存草稿，未触碰发布
}
```

推完去公众号后台「草稿箱」，**用手机预览**——SVG 动效大多只在手机端播放，PC 编辑器里可能看不到。

## 四、体积上限实测（重要更新）

**微信文档写的 2 万字符上限，实测服务端并不强制**。2026-09-03 用真实接口梯度实测：

| 提交体积 | 结果 |
|---|---|
| 26,200 字符 | ✅ 接受，存储完整 |
| 44,769 字符（violet-studio L6 全文全动效，10 SVG + 19 动画） | ✅ 接受，动画全部存活 |
| 63,325 / 150,209 字符 | ✅ 接受，存储完整 |
| **601 KB bytes（中文 22 万字符）** | ✅ 接受 |
| **≈ 690 KB bytes** | ❌ `errcode 45002: content size out of limit` |

**"少文字多动效"形态专项实测**：递增呼吸圆点动效单元（每单元 1 SVG + 2 动画），验证动效密度是否有独立上限：

| 动效单元数 | 动画标记数 | 体积 | 结果 |
|---|---|---|---|
| 100 | 200 | 42 KB | ✅ 存储 200/200 |
| 300 | 600 | 125 KB | ✅ 存储 600/600 |
| 700 | 1,400 | 293 KB | ✅ 存储 1,400/1,400 |
| 1,000 | 2,000 | 418 KB | ✅ 存储 2,000/2,000 |
| 1,400 | 2,800 | 586 KB | ✅ 存储 2,800/2,800 |
| **1,600** | **3,200** | **669 KB** | ✅ **存储 3,200/3,200（最大存活样本）** |
| 1,650 | 3,300 | 691 KB | ❌ 45002 |
| 1,700 | 3,400 | 712 KB | ❌ 45002 |

**真实上限结论**：

- 服务端**存在硬上限**：**按字节数计、与字符集无关、与内容形态无关**——纯文字和动效海报撞的是同一堵墙、同一个 45002，边界锁定在 **669 KB ~ 691 KB bytes（约 0.67 MB，并非文档暗示的 1M bytes）**；
- **动效没有独立的数量/复杂度上限**：3,200 个 SMIL 动画原样存储，只受总字节数约束；
- 超限报错 `45002`（content size out of limit），带 rid 追踪号；
- 实用安全线：**正文 payload ≤ 600 KB bytes**（含 HTML 标记），重装饰主题 + 长文也绰绰有余；
- 文档的"2 万字符"只是建议口径，服务端不强制——**但属未文档化行为，腾讯随时可能收紧**，业务关键流程建议仍按 2 万字符自律；
- ⚠️ API 层验证止步于此：**编辑器/客户端侧能否扛住 1600 单元的大草稿，API 无法探测**，草稿箱保留了一篇最大样本《动效密度阶梯 1600 单元》供人工后台打开 + 手机预览验证；
- 接口层 `draft/add`/`draft/update` 均为整篇替换语义，**不存在追加/分批能力**，也无需分批（单次上限已远超真实需求）。

各主题装饰体积参考（120 字短文实测，越长越接近线性放大）：neo-brutal ≈ 16.7K、night-editorial ≈ 17.0K、mist-research ≈ 17.1K、swiss-signal ≈ 20.0K、violet-studio ≈ 20.7K（其余 21K~44K）。`--audit` 可对任意文章精确测量。

## 六、排障速查

| 报错 | 原因 | 处理 |
|---|---|---|
| `微信接口错误 40164：invalid ip …` | 出口 IP 不在白名单 | 把报错里的 IP 加进白名单 |
| `微信接口错误 40013：invalid appid` | AppID 错 | 核对 AppID |
| `CONTENT_TOO_LARGE` / 超过 20000 | 装饰+正文超预算 | `--audit` 换轻装饰主题，或缩短文章 |
| `缺少凭证` | 无 AppID/Secret | 设环境变量或跑官方 `setup` |
| 找不到 lib | 未装官方 CLI 或装在自定义目录 | 先装官方 CLI，或设 `YITUO_HUB_GZH_HOME` |
| 存稿成功但 PC 上看不到动画 | 正常 | 用手机预览/发布后查看 |

## 七、给想改 CLI 的人（可选）

官方 CLI 只需改两行（`bin/yituo-hub-gzh.js` 的 `draftCommand` 内）：

```js
// 现在：
options.static = true;
options.motion = false;
// 改为：
options.static = flags.static === true;
options.motion = flags['preserve-visuals'] === true ? true : options.motion;
```

改完后官方 `draft` 命令带 `--preserve-visuals` 即可获得与 `l6-push.js` 相同的效果。改动前注意：默认行为（剥 SVG）是作者有意为之的省体积策略，建议以新增开关而非改默认值的方式合并。

## 八、安全边界（与官方 CLI 一致）

- AppSecret 只存本机（0600 配置文件 / 环境变量），不经过任何第三方服务器；
- 只调用 `token / uploadimg / add_material / draft/add / draft/get`，**没有发布接口**，发布权永远在公众号后台；
- 图片只在本地进程与临时目录处理。
